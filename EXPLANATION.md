# How this repo works

A technical walkthrough for anyone — human or AI coding agent — who wants to use, modify, or extend this kit. Read this before changing code. To add questions or open a PR, see [CONTRIBUTING.md](CONTRIBUTING.md).

> **If you are an AI agent:** the whole system is one JSON file (`questions.json`) plus scripts that either *produce* it (`scrape/`) or *consume* it (everything else). Never hand-edit `questions.json` — it is a build output. Section 9 lists the invariants you must not break and Section 10 the commands that prove you didn't.

## 1. The idea in one paragraph

Practice questions for the *Claude Certified Architect — Foundations* exam are scattered across community repos in different formats (JS arrays, markdown with `[CORRECT]` markers, markdown with `<details>` answers…). Per-source parsers in `scrape/` normalise each into one common JSON shape. `merge_bank.py` validates them, tags each with a *path*, removes cross-source duplicates, and writes `questions.json`. Three independent consumers read that file: an interactive CLI quiz, a markdown review-sheet generator, and a flashcard image/PDF generator.

## 4. The question schema

`questions.json` is a JSON array. Every element has exactly these 10 keys:

```json
{
  "id": "olivier-13",
  "source": "olivier",
  "path": 2,
  "domain": 1,
  "task": "1.1",
  "scenario": null,
  "stem": "The question text. May contain \n newlines and `backticks`.",
  "options": ["First option", "Second option", "Third option", "Fourth option"],
  "correct": 1,
  "explanation": "Why the correct option is right (and ideally why the others are wrong)."
}
```

| Key | Type | Rules |
|---|---|---|
| `id` | string | **Globally unique.** Convention: `<source>-<something>` (`olivier-13`, `paul-practice-40`, `sgrid-test-02-multi-agent-11`). moisesprat keeps its upstream ids (`q-csa-001`). Shown to users in results so they can look questions up. |
| `source` | string | Short lowercase name of where it came from. Used by `--source` (substring match) and printed on every question/card. |
| `path` | `1` \| `2` | Set by `merge_bank.py`, not by parsers. `1` = the original two sources (moisesprat, paullarionov) and is frozen. `2` = everything else, including all future contributions. |
| `domain` | `1`–`5` \| `null` | Exam domain. `null` = the source only labels a scenario. Drives `--domain N`, the per-domain score breakdown, and card filename prefix (`d3_…` vs `dx_…`). |
| `task` | string \| `null` | Exam task statement like `"1.1"` … `"5.6"`. String, not float. |
| `scenario` | string \| `null` | Free-text scenario name (e.g. `"Customer Support Resolution Agent"`). Drives `--scenario` (substring match). |
| `stem` | string | Non-empty. |
| `options` | string[] | 2–8 entries (every current question has 4). No `A)`/`B)` prefixes — letters are added at render time. |
| `correct` | int | **0-based index** into `options`. |
| `explanation` | string | Non-empty. A question without a "why" is not accepted — explanations are the point of the kit. |

Current bank: 388 questions · Path 1 = 163, Path 2 = 225 · 260 have a `domain` (D1 68, D2 37, D3 51, D4 55, D5 49), 128 are scenario-only.

The five exam domains and weights (duplicated as `DOMAINS` in `quiz.py` and `scrape/make_review_sheet.py`):

1. Agent Architecture and Orchestration — 27%
2. Tool Design and MCP Integration — 18%
3. Claude Code Configuration and Workflows — 20%
4. Prompt Engineering and Structured Output — 20%
5. Context Management and Reliability — 15%

## 5. `quiz.py` — the CLI

Single file, stdlib only, no classes except the colour helper. Read top to bottom:

| Piece | What it does |
|---|---|
| Constants | `BANK_PATH`, `RESULTS_DIR` (both relative to the script, so it runs from any cwd), `DOMAINS`, `PATHS` (labels only), `PASS_SCORE = 720`, `EXAM_LEN = 40`. |
| `class C` | ANSI colours. Auto-disabled when stdout is not a TTY or with `--no-color`. `clear()` is also a no-op then, so piped output is clean. |
| `wrap()`, `rule()`, `width()` | Terminal-width-aware text layout (capped at 100 cols). |
| `load_bank()` | `json.load` of `questions.json`. No caching, no mutation. |
| `filter_bank(bank, domain, source, scenario, path)` | The only selection logic. `path` matches the question's own `path` field; `domain` is exact; `source`/`scenario` are case-insensitive substring matches. Filters compose (AND). |
| `ask_question()` | Prints one question, loops on input. Returns option index, `None` (skip), or `"quit"`. Accepts as many letters as the question has options. EOF / Ctrl-C = quit. |
| `show_feedback()` | ✓/✗, the correct answer, the explanation. |
| `run_quiz(questions, mode_name, exam, feedback)` | Main loop. Collects `[(question, chosen)]`, then calls `summary()` and `write_result_md()`. `feedback=False` is exam-style (nothing revealed until the end). |
| `summary()` | Score, scaled score (exam only), per-domain breakdown, missed ids, optional re-read of missed explanations. |
| `write_result_md()` / `_md_question()` | Writes `results/result_<timestamp>_<mode-slug>.md`: summary table, then ❌ incorrect, ✅ correct, ⤼ skipped. Returns `None` (writes nothing) if no question was answered. |
| `review_mode()` | Read-only walkthrough with answers shown. No scoring, no results file. |
| `menu()` | Interactive menu. Holds two pieces of state: `scope` (path 1 / 2 / all) and `feedback` on/off. |
| `main()` | argparse. **Any** of `--exam --path --domain --scenario --source --num --review` bypasses the menu and runs once. |

**Scoring.** `scaled = round(100 + 900 × correct / total)`; pass at ≥ 720, i.e. 28/40 on a mock exam. Skipped questions count as wrong. This is a linear approximation — the real exam's scaling is not public.

**Non-interactive use (agents, CI, scripts).** The quiz reads stdin, so it can be driven by a pipe, and `--seed` makes question selection reproducible:

```bash
printf 'b\n\nq\n' | python3 quiz.py --domain 1 --num 3 --seed 7 --no-color
python3 quiz.py --review --no-color </dev/null      # print first question + answer, exit cleanly
```

## 6. The `scrape/` pipeline

All scripts here use **paths relative to `scrape/`** — always `cd scrape` first (the one exception is `make_review_sheet.py`, which resolves paths from its own location and runs from anywhere).

### Parsers

| Script | Input | Format it handles | Output |
|---|---|---|---|
| `parse_moises.cjs` (Node) | `moises_questions.js` | A JS file defining `QUESTION_BANK` and `SCENARIO_META`. The script appends a `module.exports`, writes `_moises_tmp.cjs`, `require`s it, strips HTML tags/entities. | `moises_parsed.json` |
| `parse_paul.py` | `paul_guide.md` | `## Question N (Scenario: X)` blocks; `**Situation:**`; options as `- A) …` with the right one marked `[CORRECT]`; `**Why …:**` explanation. Ids are `paul-examples-N` / `paul-practice-N`. | `paul_parsed.json` |
| `parse_path2.py` | `src_olivier/exam.md` | `**QN.**` blocks under `## Domain N:` / `### Task N.N:` headers, `**Correct Answer: X**`. | `path2_parsed.json` (all four sub-parsers append to one list) |
| 〃 | `src_dnacenta/d{1..5}.md` | `**QN:**` blocks under a "Practice Questions" heading, options as `- A) …`, `**Answer: X** — why`. Domain comes from the filename. | 〃 |
| 〃 | `src_sgrid/test-*.md` | `## Question N`, options `A) …`, answer inside `<details><summary>Answer</summary>**X)** why</details>`. Domain/task from the file's second line (`Domain 1: … -- Task Statement(s) 1.2, 1.3`); `task` is only set when the file covers exactly one task. | 〃 |
| 〃 | `src_sgrid/full-exam-01.md` | `### QN` under `## Scenario X: name` headers; same `<details>` answers. No domain. | 〃 |

Every parser: normalises smart quotes/dashes to ASCII, **silently skips** any block it cannot fully parse (missing options, answer letter out of range), and prints counts so a drop in the number is visible. Parsers do not set `path` (except `parse_path2.py`, harmlessly) — `merge_bank.py` owns that.

### `merge_bank.py`

1. Loads `moises_parsed.json` + `paul_parsed.json` → `path = 1`.
2. Loads `path2_parsed.json`, then **every other `*_parsed.json` in `scrape/`** (sorted by filename) → `path = 2`, with `domain`/`task`/`scenario` defaulted to `null` if absent. This glob is the extension point for new sources.
3. **Validates everything before writing anything** (`problem()`): required keys present and non-empty, 2–8 options, `correct` is an in-range int, no duplicate ids. On any failure it lists the offenders and exits without touching `questions.json`.
4. **Dedupes.** Signature = lowercased, punctuation-stripped `stem + options`. Two questions are duplicates when word-set Jaccard ≥ 0.5 (cheap gate) **and** symmetric `difflib.SequenceMatcher` ratio ≥ 0.62 (`autojunk=False`; threshold calibrated by hand on this bank — known genuine duplicates sit at 0.62+). Order matters: Path 1 is processed first and is never dropped; a Path 2 question that matches anything already kept is removed. Every removal is printed as `removed-id ~= kept-id` so it can be audited.
5. Writes `../questions.json` (indent 2) and prints totals by path and source.

Dedupe is O(n²) string comparison — a few seconds at ~400 questions, fine into the low thousands.

### `make_review_sheet.py`

Groups questions by domain (then scenario-only ones by scenario), sorts by `(task, source, id)`, marks the correct option ✅, and builds the "Remember" line from the first sentence or two of the explanation (truncated at 260 chars). Pure function of `questions.json` — rerun it whenever the bank changes.

## 7. Flashcards — `make_cards.py` and `make_pdf.py`

- `make_cards.py` reads `questions.json` **from the current directory** (run it from the repo root). For each question it pre-measures every text block to compute the image height, then draws: purple meta line (`DOMAIN · TASK · PATH`), scenario, bold stem, option boxes (correct one green-filled, bordered, with ✓), a "Why" box, and an `id · source` footer. Backticks are stripped. Width is fixed at 1080 px; height grows with content.
- Files are named `d{domain|x}_{NNN}_{id}.png`, where `NNN` is the position after sorting by `(domain, task, id)` — so a phone gallery scrolls in study order. Because `NNN` shifts when the bank changes, **delete `cards/` before regenerating** or stale files will end up in the PDF.
- Flags: `--no-explain`, `--path N`, `--domain N`, `--id X`, `--limit N`, `--out DIR`.
- Fonts are loaded from the hard-coded `FONT_DIR = /usr/share/fonts/truetype/dejavu` (Debian/Ubuntu default). On macOS/Windows, change that constant to a directory containing `DejaVuSans.ttf`, `DejaVuSans-Bold.ttf`, `DejaVuSansMono.ttf`.
- `make_pdf.py` sorts `cards/*.png`, downsizes each to `--width` (default 900 px), and saves one multi-page PDF. All pages are held in memory at once (~1.4 GB for the current 388 cards). Flags: `--src`, `--out`, `--width`.

## 8. Extension points

| You want to… | Touch |
|---|---|
| Add questions from a new source | Drop `scrape/<name>_parsed.json`, run `merge_bank.py` — see [CONTRIBUTING.md](CONTRIBUTING.md). No code edits needed. |
| Add a quiz mode / filter | `filter_bank()` for selection, a new `elif` in `menu()`, a flag in `main()`. |
| Change exam length / pass mark | `EXAM_LEN`, `PASS_SCORE` in `quiz.py`. |
| Track history / spaced repetition | Every run already writes a structured markdown file to `results/`; to persist machine-readable history, add a JSON append next to `write_result_md()`. |
| Build another front-end (web UI, Anki export, Telegram bot…) | Just read `questions.json` — the schema in Section 4 is the whole API. Don't import from `quiz.py`; it has no library surface. |
| Restyle cards | Layout constants and fonts at the top of `make_cards.py`; drawing in `render()`. |

## 9. Invariants — do not break these

1. `questions.json` is a **build output**. Change parsers or `*_parsed.json`, then run `merge_bank.py`. Hand edits are overwritten by the next merge.
2. Every question has all 10 keys; `correct` is a valid 0-based index; `explanation` is non-empty; ids are unique. (`merge_bank.py` enforces this.)
3. **Path 1 is frozen** (163 questions). New material is always Path 2.
4. Existing ids never change — users' saved result files reference them.
5. `quiz.py` stays **dependency-free** (stdlib only, Python 3.8+). Pillow is allowed only in the card/PDF scripts.
6. Every question keeps its `source` so upstream authors stay credited; every new source is also credited in `README.md`.
7. After any bank change, `REVIEW_SHEET.md` must be regenerated in the same commit.
8. Nothing under `cards/`, `results/`, or `flashcards.pdf` gets committed.

## 10. Verifying a change

There is no test framework; these commands are the test suite. All should succeed from the repo root:

```bash
# 1. Bank rebuilds and validates (prints counts; exits non-zero with reasons if invalid)
(cd scrape && python3 parse_paul.py >/dev/null && python3 parse_path2.py && python3 merge_bank.py)
#    add `node parse_moises.cjs` too if you touched the moisesprat parser

# 2. Schema check on the result
python3 -c "
import json, collections
q = json.load(open('questions.json'))
keys = {'id','source','path','domain','task','scenario','stem','options','correct','explanation'}
assert all(set(x) == keys for x in q), 'wrong keys'
assert all(0 <= x['correct'] < len(x['options']) for x in q), 'bad correct index'
assert len({x['id'] for x in q}) == len(q), 'duplicate ids'
assert sum(x['path'] == 1 for x in q) == 163, 'Path 1 must stay frozen'
print(len(q), 'ok', dict(collections.Counter(x['source'] for x in q)))"

# 3. Quiz still runs end to end without a TTY
printf 'a\n\nq\n' | python3 quiz.py --path 2 --num 3 --seed 1 --no-color | tail -15

# 4. Regenerate the review sheet
python3 scrape/make_review_sheet.py

# 5. (only if you touched cards) render a few
python3 make_cards.py --limit 3 --out /tmp/cards_test
```

Finally, `git diff --stat` should show only the files you meant to change — in particular, a parser tweak should not reshuffle unrelated questions in `questions.json`.

## 11. Known limitations

- 128 questions (paullarionov + the SGridworks full mock) have no `domain`, so they are excluded from `--domain N` and appear as "scenario-based" in breakdowns. Labelling them is a welcome contribution.
- The scaled score is a linear estimate, not Anthropic's real scoring.
- Dedupe thresholds are tuned to this bank; a new source with very short stems could produce false positives — always read the `~=` lines `merge_bank.py` prints.
- `make_cards.py` font path is Linux-specific (see Section 7).
- Content is unofficial and community-written; some explanations may lag behind current Claude / Claude Code behaviour. Corrections are welcome.
